# Assignment3-Marve-star

## Project

`SillyMethods` includes `didGuess42`, which checks whether a guess is 42, and `countTo`, which returns the integers from zero through the supplied number as a space-separated string. `SillyMethodsTest` contains the four assignment tests.

Run the tests from IntelliJ IDEA or with `gradle test` when Gradle is installed.

## Clean code notes: comments and formatting

### Chapter 5: Comments

- Comments cannot make unclear or misleading code clear; prefer code that explains itself through good names and structure.
- Keep comments accurate and update or remove them when the code changes. Stale comments are worse than no comments.
- Use comments to explain intent, rationale, or important context that the code cannot express, rather than to restate what the code does.
- Avoid noise comments, redundant explanations, and commented-out code; version control preserves old code.
- Be concise and precise. A comment should add useful information without becoming a second, harder-to-maintain description of the code.

### Chapter 6: Formatting

- Use formatting consistently so readers can scan code and recognize its structure.
- Keep related statements close together and organize source files from high-level ideas toward supporting details.
- Use blank lines to separate distinct thoughts, and indentation to show scope and control flow.
- Keep lines and functions manageable in length; extract cohesive work when a function becomes difficult to follow.
- Follow the project's conventions rather than mixing styles. Formatting should make relationships and nesting obvious.
